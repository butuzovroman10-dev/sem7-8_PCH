🏢 Описание предметной области: IT-Company

Иерархия классов

Вершина иерархии — абстрактный класс IWorkable. Определяет интерфейс для всех работников: два чистых виртуальных метода (work() и getEfficiency()) и виртуальный деструктор.

📌 Базовый класс Employee

  • Наследует IWorkable
  • Атрибуты: name, id, baseSalary
  • Методы: getName(), getId(), getSalary(), displayInfo()
  • Чисто виртуальные: work(), getEfficiency()

📌 Производные классы

  • Developer + язык программирования, строки кода
  • Manager + размер команды, количество встреч
  • Tester + найденные баги, инструмент тестирования

Дополнительные классы системы

📦 MyContainer<T>

  • Шаблонная коллекция
  • Внутренняя структура: отсортированный связный список
  • Методы: push_back, pop_back, remove, contains, clear

⏳ PendingQueue

  • Очередь отложенных вызовов
  • Методы: enqueue, run_one, run_all
  • Использует вариадические шаблоны

COF (Coupling Factor) — фактор сцепления

Количество реальных связей между классами:

  • IWorkable — Employee (наследование)
  • Employee — Developer (наследование)
  • Employee — Manager (наследование)
  • Employee — Tester (наследование)
  • PendingQueue — IPending (использование)
  • IPending — Pending (наследование)

Количество реальных связей = 6

Количество возможных связей = (7 × 6) / 2 = 21

COF = 6 / 21 = 0,286 (28,6%)

28,6% возможных связей реализованы — умеренное сцепление, хорошая модульность.

MHF (Method Hiding Factor) — фактор сокрытия методов

Общее число методов = 44

Число закрытых (private) методов = 6 (по 2 в Developer, Manager, Tester)

MHF = 6 / 44 = 0,136 (13,6%)

Низкий уровень сокрытия методов. Рекомендуется больше использовать private методы для инкапсуляции.

CHF (Class Hiding Factor) — фактор сокрытия атрибутов

Общее число атрибутов = 21

Число закрытых (private) атрибутов = 21 (все атрибуты объявлены как protected или private)

CHF = 21 / 21 = 1,0 (100%)

100% атрибутов скрыты — отличная инкапсуляция данных.

🔍 Анализ и рекомендации

📊 Полученные значения

  • DIT (глубина наследования): 2 — отлично, все классы находятся на небольшой глубине, легко понимать и модифицировать
  • WMC (сложность каждого класса): 5-12 — отлично, классы простые, легко тестировать
  • LCOM (связность): 0-0.33 — хорошо, методы используют общие атрибуты
  • CBO (сцепление): 0-4 — отлично, классы слабо связаны между собой
  • RFC: 3-12 — отлично, мало методов, доступных для вызова

💡 Рекомендации по рефакторингу

  1. Вынести общую логику в базовый класс Employee: Методы work() и getEfficiency() переопределяются в каждом наследнике одинаково. Можно сделать их чисто виртуальными, но добавить общую логику.
  2. Увеличить сокрытие методов: Некоторые вспомогательные методы можно сделать private вместо public.
  3. Текущая архитектура достаточно хороша для системы такого размера; радикальный рефакторинг не требуется.
